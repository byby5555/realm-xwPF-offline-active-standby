## 一、这一轮解决什么

### 1.1 缺口

真机上，交互式菜单在 **stdin 不是终端**（管道 / 后台 / cron / systemd / CI / 无人值守）时：

- `read` **立刻**返回非 0（不阻塞），变量为空；
- `case` 不匹配任何分支 → 回到 `while` 循环顶部；
- → **无限重绘 + 忙循环 + 无界输出**。

`/tmp` 是 tmpfs → 无界输出把它灌满 → 内存 + swap 耗尽 → sshd 握不上手，整机被压垮
（真机实测：5.7 小时灌满 479MB tmpfs）。

修复已入库（`100976c` / `1f5059c` / `02cc0e6`）：菜单读入统一走 helper（读到 EOF → **终止调用方**），
菜单入口加 `ui_require_tty` 护栏（stdin 不是终端就不进菜单）。

**但仓库里没有任何一条台架用例钉住它** —— 修复只过了「真机 A/B」，没有回归护栏。
下一轮谁把 helper 改回裸 `read`，没有任何用例会红。

### 1.2 本轮产出

新增 **T53**（`tests/cases/13_menu_eof_safety.sh`），钉两层：

| 层 | 钉什么 | 为什么必须有这层 |
|---|---|---|
| **第一层 · helper 契约** | 读到 EOF 时 helper 必须**终止调用方**（哨兵不出现） | 入口的 TTY 护栏会**先** exit，根本走不到 helper —— 只测入口的话，**把 helper 回退/删掉都抓不到** |
| **第二层 · 入口端到端** | 菜单入口自己退出（≠124）+ 输出字节数有上限 + 退出码 0 | 忙循环可以靠「被 timeout 杀掉」才结束，期间输出已经把缓冲区灌爆 —— 只断退出码不够 |

此外按 Chief 的 P2 派单补回 **T32 的「合法 2 份形态」分支**（§2.4），
按审稿复核的两条发现加固 **T32 的扫描范围护栏**（§2.5）与 **豁免判定**（§2.6），
并把 **T53 负向对照的输出量阈值**从「正向上限」改成「最差实测下限 + 相对量」（§三·6）。

## 二、T53 的判据细节

### 2.1 第一层 · helper 契约（4 处实现）

helper 有 4 份：`lib/core.sh`（主脚本用）+ `xwFailover.sh` / `port-traffic-dog.sh` / `speedtest.sh`
三个独立脚本**各自内置**一份。4 份都测。

判据用**哨兵**：

```
ui_read_into "T53-PROMPT" __v
echo "AFTER-CALLBACK-SENTINEL"      ← 哨兵
```

- 哨兵**不出现** = helper 终止了调用方 ✓
- 哨兵**出现** = 它没终止（坏情况）

★ **不能用退出码当判据**：helper 坏掉时脚本会继续往下跑、照样 `rc=0` → 恒绿。
★ **不能用提示语当「helper 被调用到」的标记**：bash 的 `read -p` **只在 stdin 是终端时**才打印提示语，
非终端下提示语根本不出现。改用「抽取结果非空 + 含函数定义」做静态自检。

### 2.2 第二层 · 入口端到端

菜单入口（`lib/ui.sh` 的 `show_menu`）在 `stdin=/dev/null` 下：

- 腿① 必须在超时上限内**自己**退出（退出码 ≠ 124）
- 腿② 输出字节数 ≤ 64KB（实测修复后 170 字节；修复前 5 秒灌 171,903 字节）
- 腿③ 退出码 = 0

防空过护栏两条：输出字节数 ≥ 40（空输出 = 可能根本没跑起来）；输出命中**入口标志**
（入口提示语 `终端|terminal` **或** 菜单标题 `全功能一键脚本`）。

★ **入口标志为什么接受两种**：「读到 EOF 干净退出」和「stdin 非终端直接拒绝进菜单」
两种机制都能满足「非终端时不得进入交互死循环」这个**需求**。
把护栏钉成「必须打印入口提示语」= 钉实现形态 → **另一种同样正确的形态会误红**。
（这个坑是本轮真踩到的：初版就钉了提示语，在「已修读入、未加护栏」的冻结点上误红。）

### 2.3 负向对照（两处，证明力不同，如实标注）

| 负向对照 | 用什么 | 断言什么 | 证明力 |
|---|---|---|---|
| helper 层 | **注入式退化**：把 helper 的「读到 EOF 就终止调用方」护栏去掉 | 哨兵**出现**（坏情况确实发生） | 中：helper 是修复时**新引入**的，修复前**没有等价形态** → 只能用注入式破坏，如实标注 |
| 入口层 | **真实修复前实现**（`d0366b3` 的 `lib/`，`git show` 导出） | 退出码 = 124（被 timeout 杀掉 = 忙循环）**且** 输出 ≥ 64KB | 强：真实历史实现，不是人造 |

### 2.4 P2 · T32 补回「真源 + 生成脚本内联副本」这个合法形态

第 3 轮明确放宽过 T32 的份数口径：**全仓 ∈ [1,2]**
（1 = 单一真源；2 = 真源 + 生成脚本内的手工内联副本，`a9102c1` / `b361ca8` 形态），
关键不变式是「**不许有第 3 份**」+「生成物里恰好 1 份且与真源逐字一致」，
**不是**「等于几」。后续重构里这个分支被钉成「== 1」→ 合法形态会被误判红
—— 而**手工扫描口径认它**（`reports/round2-review.md`）→ 台架比人的判据更窄 = 台架错了。

本轮按「并列分支」补回，并加了三层约束：

1. 2 份必须**同一文件**、其中一份位于生成器（`health_check_script_body`）的
   **heredoc 内**、且两份**逐字一致**（无漂移）—— 放宽 ≠ 什么都放行；
2. 期望形态由**独立事实**（份数）推出，不由被测判定器自己的结论推出 → 断言不是恒真；
3. 配 **5 组合成探针树自检**（A 单一真源 / B 真源+内联副本 / C 漂移 / D 副本分散 / E 第 3 份），
   当场证明这条分支会判对 —— 否则它在当前产品（1 份）下**一次都没被跑过**。

本轮实测（`--base-sha 2a01a33`）：判定器自检 A/B/C/D/E **全部判对**，
真实树形态判定 = **单一真源**，生成器 heredoc 内副本数 = **0**。

判定器的两个工程细节（都踩过）：

- 抽生成器 heredoc 必须按 **heredoc 自己的结束标记**收尾。正文里常有 `done` / `fi`
  这种单词行，用「单字母行」当结束标记会只抽到 14 行（真身 ~190 行）。
- 判定器跑在**命令替换（子 shell）**里 → 里面赋的全局变量在父 shell 永远是空 →
  两个字段都改成从 stdout 用 `|` 分隔输出（`cut -d'|'`，不是 `cut -f1`：
  `cut -f` 的默认分隔符是 **tab**）。

### 2.5 审稿复核 · 发现 1：扫描范围护栏只防「全砍」，不防「砍一部分」

**原状**：T32 条件 5 有一个「扫描范围下限护栏」（扫到的候选文件数 ≥ 14），
用来挡「扫描器一个文件都没扫 → 违规数必然 0 → 假绿」。
但它**挡不住「砍一部分」**：实测把候选清单里的 `docs/*` 砍掉 → 候选数 28 → 22，
**仍在下限 14 之上** → 护栏照样绿 → 而那几份文档里的误导句式**彻底无人检查**。
（这正是历史上真出过毛病的文件所在。）

**修法**：加**锚点护栏** —— 锚点用**具体文件**而不是文件数
（文件数会随文档增删漂移，锚点不会）：

```
_T32_ANCHORS="docs/active-standby-logic.md docs/health-check-and-failover.md"
```

断言「锚点文件必须在候选清单里**且**真的被扫到」，命中数必须等于锚点数。

**负向对照 8**（证明这条护栏有牙齿）：把候选清单里的 `docs/*` 砍掉 →
锚点命中数必须掉到 0（判红）；同时**对照**断言「文件数仍在下限之上」，
即**证明这一刀确实是文件数护栏挡不住的那一刀**，而不是随手砍的。

本轮实测：锚点命中 **2 / 2** ✓；负向对照 8 砍掉 `docs/*` 后锚点命中 **0**（判红）✓，
文件数 **22 ≥ 14**（对照成立）✓。

### 2.6 审稿复核 · 发现 2：整行否定豁免是漏判通道，且负向对照 6(b) 期望值写错

**原状**：T32 对「否定句」做**整行豁免**（`不需要|不存在|无需|…` 出现在行里 → 整行不算违规）。
两个问题：

1. **漏判通道**：「……两处必须同步，没有别的办法。」—— 前半句是**肯定误导**，
   句尾的「没有」让整行被豁免 → 真正的误导句式**抓不到**；
2. **负向对照 6(b) 把这种漏判写成了「正确行为」**（期望值本身写错）
   —— 负向对照在给缺陷发通行证。

**修法**：豁免缩到**子句**。

- **发现**仍由整行正则负责（不丢检测力）；**豁免判定**改用核心短语
  `两处.{0,30}同步` 定位命中位置；
- 同一**子句**内、否定词起点 **≤** 命中起点、且词尾 **≥** 命中起点 − 1 → 豁免；
  否则**计入违规**。
- 子句切分按**字节**（中文标点固定 3 字节）并钉 `LC_ALL=C`，
  **不引入中文标点字符类**（那正是 P1 的病根，见 §2.6 注）。

**负向对照 6 拆成三条**：
(a) 三行否定句确实都在（构造生效）→ (b-1) 纯否定句必须豁免 →
(b-2) **前半句是肯定误导**的那行必须**计入**（= 新口径的牙齿）。

本轮实测：构造生效 **3（≥ 3）** ✓；负向对照 6 最终结果 **1**（只有 (b-2) 计入，
纯否定句被豁免）✓。判定器另配 8 条自检（审稿表①–⑤ + 现有注入行）**8/8 全对**。

> 注：这条与 P1 是同一条纪律的两个面 —— P1 解决「判定**不得随宿主 locale 变**」，
> 本条解决「豁免范围**不得宽到放过肯定误导**」。两者都要求：字节级切分 + 钉 `LC_ALL=C`。

### 2.7 Chief 派单 P2 · 跑批前预检：负向对照依赖的历史对象在不在本地对象库

**问题**：负向对照用 `git show <SHA>:<path>` 取「修复前的真实旧实现」。
堆叠 PR 全部 squash 合并后，main 的历史里**不再包含**这些旧 SHA；
而 `git clone --single-branch` **不拉 tag** → 对象缺失 → 负向对照取不到 →
**证明力归零**，而且门禁会以「用例失败」的形式红 → **会被误读成产品回归**。

**修法**（台架 v2.12.0）：

- 清单是**单一真源**：`tests/cases/00_common.sh` 的 `sbx_required_history_shas()`
  —— 用例（取旧实现）与预检（查对象）共用同一份，不会两处漂移；
- `tests/run_tests.sh` 加 `history_preflight()`：**跑批前**逐个 `git cat-file -e`，
  缺任一个 → **独立退出码 3**（0=通过 / 1=用例失败 / 2=BASE_SHA 不存在 / 3=历史对象缺失），
  并写清：缺哪个、后果、可执行的修复命令（`git fetch --tags origin` /
  重新完整克隆 / `XWPF_FETCH_TAGS=1`）；
- 缺对象时**一个用例都不跑**（汇总行写明「预检未通过 —— 未跑任何用例」）；
- 可选自愈开关 `XWPF_FETCH_TAGS=1`（**默认不联网**，台架要能在离线机器上跑）。

**实测矩阵（`file://` 传输的真克隆，不是本地路径克隆）**：

| 腿 | 场景 | 台架 | 退出码 | 汇总行 |
|---|---|---|---|---|
| A-1 | squash 合并后的 main + `--no-tags --single-branch` 克隆（3 个旧 SHA **全不在**、无 tag） | 旧台架 v2.10.0 | **1** | 总计 2 条，通过 0，失败 2（失败项写「取不到修复前实现」）→ **这就是「被误读成产品回归」的样子** |
| A-2 | 同一个克隆 | **新台架** | **3** | 预检未通过（历史对象缺失 3 个）—— 未跑任何用例，退出码 3 |
| C | 同一个克隆 + `XWPF_FETCH_TAGS=1` | 新台架 | **0** | 总计 2 条，通过 2，失败 0（fetch --tags 把对象补回来后正常跑） |
| B-1 | **默认克隆**（拉 tag，3 个旧 SHA 都在） | 旧台架 v2.10.0 | **0** | 总计 2 条，通过 2，失败 0（断言 52 条） |
| B-1 | **默认克隆** | **新台架** | **0** | 总计 2 条，通过 2，失败 0（断言 55 条，非空 fails 0） |
| **新** | **清单为空**（台架自己坏了：清单函数没 source 到 / 清单写坏） | 新台架 | **2** | 预检清单为空 —— 未跑任何用例，退出码 2（台架配置错误） |

前两行说明**预检不改变正常克隆的任何结论**（用例数、每条断言、退出码都不变），
只是把「环境缺对象」这件事从「用例失败」挪到了「独立退出码 3」；
最后一行是**台架自己的**配置错误 → 与产品问题、与环境问题都分开（退出码 2）。

★ 造样本的纪律（否则测出来是**假绿**）：
**本地路径克隆会走本地优化，把整个对象库拷/硬链过去** → 「旧 SHA 还在」永远是假的
（实测工作克隆里 3 个 SHA 都在，就是 hardlink 假象）。
所以样本必须走 `file://` 传输做**真实 fetch**，且模拟远端要真造一个 squash 提交
（树 = 集成分支树，父 = 旧 main）—— 忠实模拟「squash 合并后的 main」。

## 三、本轮自己踩到的坑（都写进了台架纪律）

1. **防空过护栏钉死了实现形态** → 另一种同样正确的形态误红。修法：护栏接受「入口提示语 **或** 菜单标题」。
2. **判据断退出码无效**（helper 坏掉时 rc 仍为 0）→ 改用哨兵判「helper 终止调用方」。
3. **只测入口抓不到 helper 回退**（TTY 护栏先 exit）→ 必须单独测 helper 契约。
4. **跑批期间台架被改 → 那轮结果直接作废**：实测一次 `--repeat 3`，三轮每轮 52/52 PASS，
   但**退出码是 2** —— 跑批中途有人改了 `tests/run_tests.sh`，bash 按字节偏移读脚本读到错位内容。
   **表格全 PASS 也不能当结论**，必须看退出码。
5. **并行会话与共享工作区**：为避免在别人跑批时改写同一个台架文件导致其批次作废，
   本轮在**本地克隆**里验证（克隆与真实仓库 `tests/` 逐字节一致，已核验）；
   真实仓库只留待入库的改动。
6. **负向对照的阈值不能照抄「好情况的参照系」**（本轮真踩到，第 3 轮 flaky）。
   初版把负向对照的输出量下限写成 **65536 = 正向上限**；
   实测同一台机、同一台架：旧实现空闲时 5 秒吐 171,903 字节，
   而**11 路并发跑批争用下只有 63,155 字节** → 余量仅 3% → **必然 flaky**。
   实测：`--repeat 3` 的第 3 轮 T53 判红（63,155 < 65,536），前两轮全绿；
   **产品与台架本身都没问题**，是阈值取错了参照系。
   修法：负向对照要证明的是「无界输出确实发生了」，不是「超过了正向上限」→
   下限按**最差实测**取（16KB，留 3.8 倍余量），并**再加一条相对量断言**
   （旧实现输出 ≥ 50 × 当前实现输出）→ 不受机器快慢影响，恒成立。
   本轮实测放大 **789 倍**（阈值 50 倍）。
7. **放宽过的分支在重构里会被悄悄收紧**（P2 的由来）。
   T32 的份数判据第 3 轮明确放宽成「全仓 ∈ [1,2]」（1 = 单一真源；
   2 = 真源 + 生成脚本内的手工内联副本，`a9102c1` 形态），后来重构时被钉成「== 1」→
   那个**合法**形态会被误判红 —— 而**手工扫描口径认它**（`reports/round2-review.md`）
   → 台架比人工口径更窄 = 台架错了。
   补法：按「并列分支」写回去，并**当场证明它会判对**：
   配 5 组合成探针树自检（单一真源 / 真源+内联副本 / 漂移 / 副本分散 / 第 3 份）。
   不配的后果：当前产品只有 1 份 → 「2 份」那条分支**一次都没被跑过**
   → 判定器写错了也是全绿。
8. **负向对照的「期望值」写错 = 给缺陷发通行证**（审稿复核发现 2）。
   负向对照 6(b) 原来把「肯定误导 + 句尾否定词」当成**正确行为**（期望豁免）
   —— 断言照着实现写，缺陷就被固定住了。
   纪律：**期望值必须由独立事实推出**，不能照着当前行为写；
   尤其「豁免类」断言要单独问一句「它豁免的到底是哪一种行」。
9. **预检自己也会静默放行**（写完预检后立刻自己抓到）。
   预检读清单的循环是 `while read ... done < <(sbx_required_history_shas)`；
   若那个函数**不可用**（没 source 到 / 清单写坏）→ 循环读不到任何行 →
   `n_total=0`、`n_missing=0` → 直接 `return 0` → **预检一个对象都没查却报「通过」**
   → 历史对象缺失会被静默吞掉（= 假绿）。
   修法：清单为空 → **响亮失败**，退出码 2（台架配置错误，不是产品问题、也不是环境问题）。
   实测（注入式退化：把清单函数改成不产出任何条目）→ 退出码 **2**，
   输出含「历史对象清单为空」并写明后果与检查点。
   ★ 这条是本轮**自己审自己**抓出来的：写完预检后顺手问了一句
   「清单读不到时它会怎么判」→ 发现它会**放行**。
10. **退出码被一律映射 → 输出说了假话**。
    预检有**两种**失败：「历史对象缺失」(3) 与「台架清单为空」(2)，
    但调用点写成 `if ! history_preflight; then exit 3; fi` → 两种都被报成 3，
    而空清单那条的输出里明明写着「退出码 2」→ **台架自己说的话与实际退出码对不上**
    （这正是 T40 那类「必须引用真实输出」问题的变种）。
    修法：退出码**原样透传**（`history_preflight || _pf_rc=$?` → `exit "$_pf_rc"`）。
    实测：空清单 → 实际退出码 **2**，与输出里的说明一致。
11. **「本地路径克隆」是假绿的制造机**（预检实测踩到）。
   `git clone <本地路径>` 会把**整个对象库**拷/硬链过去 → 「旧 SHA 还在」永远是假的；
   工作克隆里 3 个历史 SHA 都在，就是 hardlink 假象。
   验证「某个 SHA 还在不在」必须走 **file:// / https 真实传输**（真 fetch），
   且造样本要真造一个 squash 提交，否则测的是「假想场景」。

## 五、遗留与建议

1. **T51 的探针断言没有时延余量**：本机本地回环在沙箱里要 0.1~2.3 秒，
   观测到 1 次探测被 timeout 杀掉（复跑又是 112ms 通过）→ 这条会偶发红。
   建议放宽探测超时，或换成不受回环时延影响的探针手段。
2. **N2（`/tmp` 无界输出）** 仍是待办；T53 钉的是**入口不忙循环**，
   还没有钉「任何输出都要有上限」这条更宽的不变式。
   （产品侧的 N2 修复已由用户提交 `12f63f9` / `7c95dca`，但那是**崩溃循环**，
   与本条的「无界输出」不变式不是一回事。）
3. **真机侧**：T53 只在沙箱里跑；`ETXTBSY` 那类 Linux 内核行为仍需真机复验。
