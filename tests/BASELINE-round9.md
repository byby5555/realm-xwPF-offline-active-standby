## 一、这一轮解决什么

### 1.1 缺口

真机上，交互式菜单在 **stdin 不是终端**（管道 / 后台 / cron / systemd / CI / 无人值守）时：

- `read` **立刻**返回非 0（不阻塞），变量为空；
- `case` 不匹配任何分支 → 回到 `while` 循环顶部；
- → **无限重绘 + 忙循环 + 无界输出**。

`/tmp` 是 tmpfs → 无界输出把它灌满 → 内存 + swap 耗尽 → sshd 握不上手，整机被压垮
（真机实测：5.7 小时灌满 479MB tmpfs）。

修复已入库（`100976c` / `1f5059c` / `02cc0e6`）：菜单读入统一走 helper（读到 EOF → **终止调用方**），
菜单入口加 `ui_require_tty` 护栏（stdin 不是终端就不进菜单）。

**但仓库里没有任何一条台架用例钉住它** —— 修复只过了「真机 A/B」，没有回归护栏。
下一轮谁把 helper 改回裸 `read`，没有任何用例会红。

### 1.2 本轮产出

新增 **T53**（`tests/cases/13_menu_eof_safety.sh`），钉两层：

| 层 | 钉什么 | 为什么必须有这层 |
|---|---|---|
| **第一层 · helper 契约** | 读到 EOF 时 helper 必须**终止调用方**（哨兵不出现） | 入口的 TTY 护栏会**先** exit，根本走不到 helper —— 只测入口的话，**把 helper 回退/删掉都抓不到** |
| **第二层 · 入口端到端** | 菜单入口自己退出（≠124）+ 输出字节数有上限 + 退出码 0 | 忙循环可以靠「被 timeout 杀掉」才结束，期间输出已经把缓冲区灌爆 —— 只断退出码不够 |

## 二、T53 的判据细节

### 2.1 第一层 · helper 契约（4 处实现）

helper 有 4 份：`lib/core.sh`（主脚本用）+ `xwFailover.sh` / `port-traffic-dog.sh` / `speedtest.sh`
三个独立脚本**各自内置**一份。4 份都测。

判据用**哨兵**：

```
ui_read_into "T53-PROMPT" __v
echo "AFTER-CALLBACK-SENTINEL"      ← 哨兵
```

- 哨兵**不出现** = helper 终止了调用方 ✓
- 哨兵**出现** = 它没终止（坏情况）

★ **不能用退出码当判据**：helper 坏掉时脚本会继续往下跑、照样 `rc=0` → 恒绿。
★ **不能用提示语当「helper 被调用到」的标记**：bash 的 `read -p` **只在 stdin 是终端时**才打印提示语，
非终端下提示语根本不出现。改用「抽取结果非空 + 含函数定义」做静态自检。

### 2.2 第二层 · 入口端到端

菜单入口（`lib/ui.sh` 的 `show_menu`）在 `stdin=/dev/null` 下：

- 腿① 必须在超时上限内**自己**退出（退出码 ≠ 124）
- 腿② 输出字节数 ≤ 64KB（实测修复后 170 字节；修复前 5 秒灌 171,903 字节）
- 腿③ 退出码 = 0

防空过护栏两条：输出字节数 ≥ 40（空输出 = 可能根本没跑起来）；输出命中**入口标志**
（入口提示语 `终端|terminal` **或** 菜单标题 `全功能一键脚本`）。

★ **入口标志为什么接受两种**：「读到 EOF 干净退出」和「stdin 非终端直接拒绝进菜单」
两种机制都能满足「非终端时不得进入交互死循环」这个**需求**。
把护栏钉成「必须打印入口提示语」= 钉实现形态 → **另一种同样正确的形态会误红**。
（这个坑是本轮真踩到的：初版就钉了提示语，在「已修读入、未加护栏」的冻结点上误红。）

### 2.3 负向对照（两处，证明力不同，如实标注）

| 负向对照 | 用什么 | 断言什么 | 证明力 |
|---|---|---|---|
| helper 层 | **注入式退化**：把 helper 的「读到 EOF 就终止调用方」护栏去掉 | 哨兵**出现**（坏情况确实发生） | 中：helper 是修复时**新引入**的，修复前**没有等价形态** → 只能用注入式破坏，如实标注 |
| 入口层 | **真实修复前实现**（`d0366b3` 的 `lib/`，`git show` 导出） | 退出码 = 124（被 timeout 杀掉 = 忙循环）**且** 输出 ≥ 64KB | 强：真实历史实现，不是人造 |

## 三、本轮自己踩到的坑（都写进了台架纪律）

1. **防空过护栏钉死了实现形态** → 另一种同样正确的形态误红。修法：护栏接受「入口提示语 **或** 菜单标题」。
2. **判据断退出码无效**（helper 坏掉时 rc 仍为 0）→ 改用哨兵判「helper 终止调用方」。
3. **只测入口抓不到 helper 回退**（TTY 护栏先 exit）→ 必须单独测 helper 契约。
4. **跑批期间台架被改 → 那轮结果直接作废**：实测一次 `--repeat 3`，三轮每轮 52/52 PASS，
   但**退出码是 2** —— 跑批中途有人改了 `tests/run_tests.sh`，bash 按字节偏移读脚本读到错位内容。
   **表格全 PASS 也不能当结论**，必须看退出码。
5. **并行会话与共享工作区**：为避免在别人跑批时改写同一个台架文件导致其批次作废，
   本轮在**本地克隆**里验证（克隆与真实仓库 `tests/` 逐字节一致，已核验）；
   真实仓库只留待入库的改动。

## 五、遗留与建议

1. **T51 的探针断言没有时延余量**：本机本地回环在沙箱里要 0.1~2.3 秒，
   观测到 1 次探测被 timeout 杀掉（复跑又是 112ms 通过）→ 这条会偶发红。
   建议放宽探测超时，或换成不受回环时延影响的探针手段。
2. **N2（`/tmp` 无界输出）** 仍是待办；T53 钉的是**入口不忙循环**，
   还没有钉「任何输出都要有上限」这条更宽的不变式。
3. **真机侧**：T53 只在沙箱里跑；`ETXTBSY` 那类 Linux 内核行为仍需真机复验。
