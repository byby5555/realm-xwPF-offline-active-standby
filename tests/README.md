# 测试目录

本地回归测试（Git Bash / Linux / macOS 均可跑，**不需要 root**，不会碰真实的 `/etc/realm`）。

> **第 2 轮起本目录只有一个入口：`bash tests/run_tests.sh`。**
> 其它 `tests/test_*.sh` 全部退化成**薄封装**（内部 `exec` 到 `run_tests.sh --only ...`），
> 保留它们只是为了不打断别人的调用习惯 —— 它们**不是独立门禁**，跑出来的结论与主入口完全同源。
> 「全过」这个词只认 `run_tests.sh` 的输出。

---

## 跑法

```bash
# 主入口（唯一）
bash tests/run_tests.sh                      # 跑全部 51 条用例
bash tests/run_tests.sh --only T06,T18       # 只跑指定用例
bash tests/run_tests.sh --repeat 3           # 连跑 3 轮，校验结果向量一致
bash tests/run_tests.sh --list               # 列出用例编号
bash tests/run_tests.sh --clean              # 跑完删掉沙箱

# 冻结点（第 2 轮新增，强烈建议正式跑批时显式指定）
BASE_SHA=a9102c1 bash tests/run_tests.sh
bash tests/run_tests.sh --base-sha a9102c1   # 等价写法

# T40 的扫描窗口（第 5 轮新增，默认 20 条）
COMMIT_CHECK_N=50 bash tests/run_tests.sh --only T40
```

退出码：`0` = 全部通过；非 `0` = 有失败。

### 冻结点机制（一句话）

被测产物一律从 `git show $BASE_SHA:<path>` 导出，**不读工作区文件**。
`BASE_SHA` 默认取当前 `HEAD`；正式跑批请显式指定，报告里必须写上这个 SHA。
**SHA 一变，旧结论全部作废，必须重跑。**

细节见 [`tests/TEST-HARNESS.md`](./TEST-HARNESS.md)。

## T02 的自指风险（第 5 轮固化）

T02 断言「仓库里不许再出现旧仓库名 `zywe03/realm-xwPF`」。
但**断言文件自身必然含有这个字符串** —— `tests/cases/01_static_contract.sh` 里
`REPO_OLD="zywe03/realm-xwPF"` 就是被禁字符串本身，注释里也要写明它禁的是什么。

> **断言文件自身含被禁字符串是正常的；但统计必须排除断言自身**，
> 否则将来只要改动 T02 的逻辑（哪怕只改一句注释、换一个变量名），
> 统计就会把自己数进去 → 出现跟产品无关的**自指假红**。

所以 T02 的统计口径固定为 `grep -rnF "$REPO_OLD" "$SBX_SRC" --exclude-dir=tests`
（`$SBX_SRC` 是冻结态副本，里面也含 `tests/`，**排除是必要的**），
并且第 5 轮把这件事变成**可验证的三条断言**：

| # | 断言 | 作用 |
|---|------|------|
| 1 | 排除 `tests/` 后命中 **0** 条 | 产品与文档干净 |
| 2 | 全树命中中落在 `tests/` 之外的 **0** 条 | 证明「排除 `tests/`」没有掩盖任何外部残留 |
| 3 | 冻结树里 `tests/` 内命中 **≥ 1** 条 | 证明排除确实是**必要的**（断言自身确实含被禁字符串），不是多余的 |

第 3 条在冻结点没有 `tests/cases/01_static_contract.sh` 时（例如很老的老冻结点）自动跳过并记日志。
改这条用例时**不要**把排除规则去掉 —— 去掉后第 1 条会因为数到自己而变红，那是自指假红不是产品缺陷。

## T40 的提交信息契约（第 5 轮新增）

### 为什么要有

第 1 轮实测出过事故：**另三套脚本全绿、正式入口 `run_tests.sh` 16/22 红，提交信息却写「全过」**。
第 2 轮把这件事做成了跑批末尾的**打印告警** —— 但告警拦不住任何人。
第 5 轮把同一套判定搬进用例 **T40**：违规就是**用例失败、门禁退出码非 0**。

### 判定规则

对最近 N 条提交信息（`COMMIT_CHECK_N`，默认 20，锚定 `BASE_SHA`）逐条判：

1. **命中「声称全过」词表**才进入判定 —— 没命中一律放行
   （词表：`全过 / 全部通过 / 全通过 / 都通过 / 全绿 / 测试通过 / 用例通过 / 断言全过 / 场景全过 /
   失败 0 / N\/M 通过 / N 条…通过 / all tests passed / tests passed`）。
2. 声称全过的提交必须**同时**给出：
   - ① 唯一入口引用：出现 `run_tests.sh`
   - ② 实测口径：`BASE_SHA`（7~40 位十六进制）/ 汇总行 / 用例总数 / 退出码（任一即可）
   - 缺 ① 或缺 ② → **违规 → 用例失败**，并打印「哪条提交 / 命中了哪个词 / 缺了什么」。
3. **旧格式容忍**：① ② 都在但缺 `BASE_SHA` → 判过，只记一条提示。
   历史提交里确实存在「只写『22 条通过』没写 SHA」的合法旧格式，不追溯重写历史。
4. **自动豁免**：该提交的树里还没有 `tests/run_tests.sh`（唯一入口当时尚不存在）→ 不追溯要求。
5. **过渡白名单**：`tests/commit-msg-exemptions.txt`，**上限 3 条**，每条必须写明豁免理由，
   每条的 SHA 必须能在仓库里解析到提交。

### 提交信息该怎么写

```
fix(x): 修了某某行为

自测：tests/run_tests.sh @<BASE_SHA>
汇总: 总计 51 条，通过 51，失败 0
```

`BASE_SHA` 与汇总行都带上最稳（口径 A）；只给其中一种也能过（口径 B），
但缺 `BASE_SHA` 时台架会记一条「旧格式」提示。

### 反例自检

T40 内部用**内存里的**假提交信息（**不产生任何真实提交**）跑 6 组对照：
3 条坏消息必须被判违规、3 条好消息必须被放行，并额外断言「抓到 3 条 / 放过 3 条」。
这是「怎么写都绿」的防护 —— 规则本身也要被测。

第 2 轮把原来 4 套独立脚本的用例并入 `run_tests.sh`，脚本本身保留为薄封装；
第 7 轮把剩下 2 套也并进来 —— **不留第二个入口**：

| `tests/test_set_u.sh` | `run_tests.sh --only T31` | 对照组 + 生成不中断 + 输出一致 + 其他函数健壮 |
| `tests/test_update.sh` | `run_tests.sh --only T43,T44,T45,T46,T47`（**第 7 轮**） | 更新中心：版本归一化 / 校验不过拒绝装 / 回滚健壮性 / 自动回滚 / 脚本包更新 + 锁 |

## `tests/shims/` —— 离线替身

给「装一遍 / 跑一遍完整流程」用的假命令，把外部依赖换成本地可控行为：

| 替身 | 作用 |
|------|------|
| `curl` / `wget` | 离线下载桩：按 URL 里的 `/main/`、`/raw/` 取仓库相对路径，到 `$SBX_MIRROR` 本地镜像取文件；取不到返回 404。**每次调用都记录 URL**，可断言「下载地址是否都指向本 fork」 |
| `nc` | 模拟 TCP 探测结果：`$SBX_NC_DOWN` 里每行一个 `host:port`，命中即判连接失败 |
| `systemctl` | 只记录调用；`is-active` / `is-enabled` 返回 3（inactive） |
| `flock` | 假锁（Git Bash 没有 flock） |
| `id` | 永远返回 root |
| `bc` | 只支持 `scale=N; a * b / c` 这一种表达式 |
| `apt-get` / `journalctl` / `realm` | 只记录不执行 |
| `jq` | **mini-jq 桩**（实现见同目录 `jq_impl.py`）：本机没有 jq，而仓库里有 119 处 jq 调用 —— 不装桩就等于「整段依赖 jq 的配置生成路径」完全没被测过。桩只实现仓库真实用到的过滤语法，**能力不够必须显式报「桩能力不足」+ 退出码 3**，绝不静默返回空值假装测过；且**能力检测与数据无关**（先做一遍语法校验，数据走不到分支也必须报） |

> **jq 桩的三条纪律**（第 7 轮固化）：
> 1. **不会就说不会** —— 不支持的过滤器 → stderr 打印「jq-stub: 桩能力不足：\<表达式\>」+ 退出码 3，
>    让调用方的兜底分支真的走到，而不是悄悄拿到空值。
> 2. **能力检测与数据无关** —— 先验语法校验，再求值。否则「数据刚好没走到那个分支」时
>    就会静默返回空值 → 看起来测过了，其实没测。
> 3. **拒绝「会被静默误解」的危险语法** —— 比如 `..`（jq 的递归下降）：桩原本会把它
>    解析成「整个对象」，**结果看着有输出但语义全错**。这类语法必须报「不会」，
>    不能给一个看着对的错答案。
>
> 桩输出统一为**紧凑 JSON**（`jq -c` 的形态）；真 jq 默认是缩进输出，差别只在空白，
> 不影响 JSON 语义 —— 所以用例断言一律按**语义**判，不按字节。

用法：

```bash
export SBX_LOG_DIR=/tmp/shimlog
export SBX_MIRROR=/path/to/local/mirror
export SBX_NC_DOWN=/tmp/down_targets
export PATH="$PWD/tests/shims:$PATH"
```

> `tests/shims/` 里只放**替身**，不放真实业务逻辑；
> 被测对象始终是冻结态里的 `lib/*.sh` 与 `xwFailover.sh`。

## 写用例时的几条硬规矩

1. **断言行为，不钉实现位置**。不要断言「函数在哪个文件里」，要断言「跑出来的结果是什么」。
   （T06 就是这么从「钉文件」改成「钉行为」的。）
2. **静态检查读冻结态**，不要读工作区，也不要用 `git ls-files --eol`（查的是索引，不是冻结态）。
3. **不要在文件头把沙箱路径快照成变量**。用例文件是在沙箱建好**之前**被 source 的，
   那时 `$SBX_SRC` 还是空的 —— 快照下来会变成「读不到任何文件 → 0 命中 → 判过」的假绿。
   一律在用例函数体内直接用 `"$SBX_SRC"`。
4. **fixture 只做参数化，不裁剪键集**。规则文件要写全官方键集（见 `lib/server.sh` 的模板），
   否则 `read_rule_file` 的 `unset` 会让缺失的键变成未定义变量。
5. **一条红灯要能被第二口径交叉验证**。先确认「是不是用例自己错了」，再报缺陷。
6. **新断言必须有负向对照**。写完先往冻结态副本里注入一个坏输入，确认它**会红** ——
   「怎么写都绿」的断言等于没有断言。T34 的负向对照做过 4 组：
   注入不存在的符号 → 抓；注入不存在的源文件 → 抓；注入越界行号 → 抓；
   把 `auto_enable_active_standby` 改名 → 抓（这就是 D-01 那类回归）。
7. **命中数要有下限护栏**。像 T34 这种「解析 N 处引用」的用例，
   正则一坏就是 0 命中 → 断言全过 → 假绿。所以另加一条「命中数 ≥ N」的断言（N 取实测值的 ~1/2）。
8. **别断言交互提示的文本，断言行为**。bash 的 `read -p` 只在 **stdin 是终端**时才把提示打到 stderr
   （bash 手册原文：*"The prompt is displayed only if input is coming from a terminal."*）。
   沙箱里喂的是管道 → **提示根本不显示** → 断言提示文本必然失败。
   正确做法：断言**行为**（答 `n` 会不会取消、回车会不会继续），
   提示是否显示属于 TTY 行为，不在台架的判定范围内。
9. **对照组必须用对函数**。「进不进主备」由 `apply_port_group_weight_config` 的**权重判定**决定，
   `auto_enable_active_standby` 本身不看权重、只要被调用就会切主备 ——
   拿它做「不进主备」的对照组会得到假红。
10. **断言文件自身含被禁字符串是正常的，但统计必须排除断言自身**。
    否则改一下断言的逻辑（改注释、换变量名）就会自指假红 ——
    红了也不代表产品坏了。T02 是这条规矩的样板（见上文「T02 的自指风险」），
    做法是：排除规则写进代码注释 + 本文件，并且用「全树命中里落在 `tests/` 之外的条数 = 0」
    这条断言把排除的有效性**变成可验证的**，而不是靠一句注释维持。
11. **「打印告警」不是门禁**。会让人以为「已经检查过了」的提示，必须升级成**可失败的用例**。
    T40 就是这么来的：第 2 轮末尾那句 ⚠ 提示拦不住任何人，第 5 轮变成用例失败 + 非 0 退出码。
    判定器本身也要被测 —— T40 内置 6 组反例自检（内存造消息，不产生真实提交）。
12. **豁免机制要有上限、要有理由、要有负向对照**。白名单不是垃圾桶：
    条数上限（≤3）、每条必写理由、SHA 必须可解析，三条约束都做过负向对照（破坏任一条 → 判红）。
13. **不变式必须覆盖所有合法形态，不能只覆盖当前形态**（第 7 轮 T32 的教训）。
    断言钉住的是「**不变式**」，不是「当前实现长什么样」。
    自查一句：「把实现换成另一种同样正确的形态，它会不会误红？」
    —— 旧 T32 钉的是「生成物里内嵌 1 份探测实现」，现在钉的是
    「**生成物的探测逻辑与真源是否一致**」（形态 A 内嵌 / 形态 B source 真源都判过）。
14. **破坏手法要按语义定位，别钉死代码文本**（第 7 轮 T51 的教训）。
    `sed 's|某个具体写法|...|'` 在实现一改（缩进 / 写法 / 收敛成单一函数）就静默失效，
    看着像生效了其实没对准。优先改**判定条件**、改**函数名**，
    或在副本**末尾追加一个同名函数覆盖**（bash 里后定义覆盖先定义，一定生效）。
    并且**先验证破坏生效**（注入点计数 == 1 / 坏值真的出现）再信它的红 ——
    「负向对照红了」先怀疑「破坏手法」，再怀疑「被测代码」。
15. **负向对照要隔离真实缺陷**。负向对照若建在**冻结态整棵树的副本**上，
    真实存在的缺陷会混进命中数 → 负向对照就变成「在测真实缺陷」而不是「在测扫描器」。
    做法：用**合成探针树**（只放一个候选文件）跑扫描器，命中数才干净。
16. **跑批期间不要改台架脚本**。bash 按字节偏移读脚本；跑批中途改文件会让它读到错位的片段
    → 尾部报莫名其妙的语法错。改台架 → 改完**重跑**再取结论。
