## 1. 本轮台架变更

### 1.1 T40：提交信息契约 —— 从「打印告警」升级为**可失败的硬断言**

第 1 轮出过事故：**另三套脚本全绿、正式入口 `run_tests.sh` 16/22 红，提交信息却写「全过」**。
第 2 轮把这件事做成了跑批末尾的 ⚠ 打印告警 —— 但告警拦不住任何人。
第 5 轮把同一套判定搬进用例 **T40**：违规 = **用例失败 + 门禁退出码非 0**。

**判定规则**（对最近 N 条提交信息，`COMMIT_CHECK_N` 默认 20，锚定 `BASE_SHA`）：

1. 命中「声称全过」词表才进入判定 —— 没命中一律放行。
   词表：`全过 / 全部通过 / 全通过 / 都通过 / 全绿 / 测试通过 / 用例通过 / 断言全过 / 场景全过 /
   失败 0 / N\/M 通过 / N 条…通过 / all tests passed / tests passed`
2. 声称全过的提交必须**同时**给出：
   - ① **唯一入口引用**：出现 `run_tests.sh`
   - ② **实测口径**：`BASE_SHA`（7~40 位十六进制）/ 汇总行 / 用例总数 / 退出码（任一即可）
   - 缺 ① 或缺 ② → **违规 → 用例失败**，并打印「**哪条提交 / 命中了哪个词 / 缺了什么**」。
3. **旧格式容忍**：①②都在、只缺 `BASE_SHA` → 判过，只记一条提示
   （历史提交里确实有「只写『22 条通过』没写 SHA」的合法旧格式，不追溯重写历史）。
4. **自动豁免**：该提交的树里还没有 `tests/run_tests.sh`（唯一入口当时尚不存在）→ 不追溯要求。
5. **过渡白名单** `tests/commit-msg-exemptions.txt`：**上限 3 条**，每条必写理由，SHA 必须可解析。

**反例自检（判定器本身也要被测）**：用例内构造**内存里的**假提交信息（**不产生任何真实提交**），6 组对照：

| # | 构造的假提交信息 | 期望判定 | 实测 |
|---|------------------|----------|------|
| ① | `测试全过`（什么都不引用） | 违规 | ✅ BAD |
| ② | `测试全过（bash tests/run_tests.sh）`（引用入口、无口径） | 违规 | ✅ BAD（缺失项写的是「实测口径」） |
| ③ | `tests/test_latency.sh 33 项断言全过`（引用**别的**脚本） | 违规 | ✅ BAD（第 1 轮事故原型） |
| ④ | `feat(x): 新增一个功能，未触及测试逻辑` | 放行 | ✅ NOCLAIM |
| ⑤ | `测试全过` + `tests/run_tests.sh @60070e8` + `汇总: 总计 40 条，通过 40，失败 0` | 放行 | ✅ OK |
| ⑥ | `测试全过` + `tests/run_tests.sh @60070e8` + `退出码 0` | 放行 | ✅ OK |

外加两条计数护栏：「应抓住 3 条 / 应放过 3 条」—— 防止自检本身空过。

**白名单三条硬约束的负向对照**（每条都实测过「破坏 → 判红」）：

### 2.2 T02 的自指风险：查了什么、怎么固化的

**查证结论**：`tests/cases/01_static_contract.sh` 的 T02 统计口径**本来就排除了 `tests/` 目录**：

```bash
hits=$(grep -rnF "$REPO_OLD" "$SBX_SRC" --exclude-dir=tests 2>/dev/null)
```

- 被测面是冻结态 `$SBX_SRC`（= `git show $BASE_SHA:<path>` 的 LF 副本），**里面也含 `tests/`**；
- 断言文件 `tests/cases/01_static_contract.sh` 自身写着 `REPO_OLD="zywe03/realm-xwPF"`（还多一处说明文字）；
- → **不排除就会数到自己** → 改一下断言的逻辑（哪怕只改一句注释、换一个变量名）就会自指假红。

**冻结态实测分布**（三个冻结点一致）：全树命中 **5 处，全部落在 `tests/` 内**，落在 `tests/` 之外的 **0 处**：

```
tests/BASELINE-round1.md:64
tests/BASELINE-round1.md:144
tests/cases/01_static_contract.sh:12     ← 断言自身
tests/cases/01_static_contract.sh:78     ← 断言自身
tests/README.md:45
```

**本轮的固化做法（不只是写注释，是加断言）**：

| # | 断言 | 守什么 |
|---|------|--------|
| 1 | 排除 `tests/` 后命中 **0** 条 | 产品与文档干净（原断言，保留） |
| 2 | 全树命中中落在 `tests/` 之外的 **0** 条 | **证明「排除 `tests/`」没有掩盖任何外部残留** |
| 3 | 冻结树里 `tests/` 内命中 **≥ 1** 条 | **证明排除确实是必要的**（断言自身确实含被禁字符串），不是多余的 |

第 3 条在冻结点没有 `tests/cases/01_static_contract.sh` 时（很老的老冻结点）自动跳过并记日志。

**同步落笔的地方**：
- `tests/cases/01_static_contract.sh` 的 T02 函数头注释 —— 写明「断言文件自身含被禁字符串是正常的，但统计必须排除断言自身，否则将来改逻辑就会自指假红」；
- `tests/README.md` 新增「**T02 的自指风险（第 5 轮固化）**」小节 —— 同一段说明 + 三条断言表；
- `tests/TEST-HARNESS.md` 断言纪律第 7 条。

> **产品代码零改动** —— 本轮只动了 `tests/` 目录。
