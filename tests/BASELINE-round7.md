## 2. T32 的改造：不变式必须覆盖所有合法形态

Chief 指出 T32 的**条件 4 钉住了一种实现形态**，本轮已改。

### 2.1 条件 4：判「探测逻辑与真源是否一致」，不判「是不是内嵌的」

| 形态 | 描述 | 判定 |
|------|------|------|
| **形态 A** | 生成物内含 1 份 `check_connectivity() {`，且与真源逐字一致 | ✅ 过 |
| **形态 B** | 生成物**不含**内嵌副本，但显式 `source` 已安装的真源（且该路径能解析到真源） | ✅ 过 |
| 其余 | 内嵌多份 / 逐字漂移 / 既不内嵌也不 source / source 路径解析不到 | ❌ 红 |

> 旧断言写的是「生成物里 `check_connectivity() {` 恰好 1 份」——
> 这只对「机械抽取内嵌」这一种实现成立。将来改成「source 真源」（依赖更少、漂移风险更低，
> 是**产品变好**）就会误红。

### 2.2 条件 5：正则收紧到「肯定误导句式」

- 只匹配**肯定**误导句式：`改动…两处…同步` / `两处必须同步` / `需两处同步` / `必须两处同步`；
- **同一行含否定词**（不需要 / 不存在 / 无需 / 无须 / 不再 / 不必 / 不用 / 不涉及 / 并非 / 没有）→ 整行豁免；
- 描述性的「内含一份同源的探测副本」**不单独算违规** —— 形态 A 下生成物确实含一份副本，
  这句话是真的，错的只有「要手工同步」。把它也算违规 = 又把断言钉回某一种形态；
- 加**扫描范围下限护栏**（扫描到的候选文件数 ≥ 14，实测 28）——
  「违规数 == 0」最大的假绿风险是「扫描器一个文件都没扫」。

> **收紧后立刻暴露了一个真缺陷**：`docs/active-standby-logic.md` 的表格行仍写着
> 「内含一份同源的探测副本，改动需两处同步」——
> 旧正则 `另有一份内联副本|两处必须同步` 匹配不到「内含一份同源」和「需两处同步」，
> 所以 `b9b4c5e` 那次改写（同文件改了 3 处）漏掉这一行时门禁仍然是绿的。
> → **R7-D01**，直发小编，`f730c8b` 已修。

### 2.3 T32 的 6 条负向对照（全部已验证「破坏手法生效」再信它的红）

## 3. jq 桩（本轮新增，第 7 轮的关键基础设施）

本机没有 jq，而仓库里有 **119 处** jq 调用 —— 不装桩就等于「整段依赖 jq 的配置生成路径」
**完全没被测过**。`tests/shims/jq`（实现 `tests/shims/jq_impl.py`）是只覆盖仓库真实用到的
过滤语法的 mini-jq。

**三条纪律：**

1. **不会就说不会** —— 不支持的过滤器 → stderr 打印「jq-stub: 桩能力不足：\<表达式\>」+ **退出码 3**，
   让调用方的兜底分支真的走到，而不是悄悄拿到空值。
2. **能力检测与数据无关** —— 先验语法校验，再求值。
   否则「数据刚好没走到那个分支」时就会静默返回空值 → 看起来测过了，其实没测。
3. **拒绝「会被静默误解」的危险语法** —— 比如 `..`（jq 的递归下降）：
   桩原本会把它解析成「整个对象」，**结果看着有输出但语义全错**。这类语法必须报「不会」。

本轮对桩做的 3 处扩展（都是被产品真实用法逼出来的）：

| 扩展 | 为什么需要 |
|------|------------|
| **段后面的数组下标** `.endpoints[0]` | 原来只认「`.` 后面紧跟 `[`」→ `.endpoints[0]` 被解析成整个数组，OCR 读单个 endpoint 全空（**静默失败**） |
| **`-e` 退出码语义** | 原来 `-e` 被忽略 → `.endpoints` 这类「不存在就是 null」的判空永远成功 |
| **JSON 对象/数组字面量** | `port-traffic-dog.sh` 用 `jq ".\"$port\" = {\"input\": $v, ...}"`，bash 先把 `$v` 插值进过滤器文本 → 传进 jq 的是一段合法 JSON |

桩输出统一为**紧凑 JSON**（`jq -c` 的形态）；真 jq 默认缩进输出，差别只在空白 →
用例断言一律按**语义**判，不按字节。

**桩的覆盖边界（不假装测过）**：
- 桩**只**实现仓库实际用到的过滤器。将来产品引入新语法 → 桩会**显式**报「桩能力不足」+ 退出码 3，
  届时 T49 会红，而不是「静默返回空值 → 假装测过」。
- `port-traffic-dog.sh` 的流量计费路径不在本轮 T49 范围内（那不是「配置生成」）。

## 4. 收尾：跟随产品 `a7e23fc` 的口径变更（TARGET 改 host:port）

### 4.1 发生了什么

产品把健康状态文件第 2 字段 TARGET 从**裸 host** 改成 **`host:port`**：
同一个 host 上跑不同端口的两个转发组，状态不再互相覆盖。
（修复前：读取侧只用 host 建索引 → A 组的故障被 B 组的健康记录盖掉 → 该切不切，故障转移静默失效。）

**被测产物变了 → 旧结论作废**，必须在 `a7e23fc` 上重跑。重跑时门禁出现 1 条红灯：

| 用例 | 现象 | 判定 |
|------|------|------|
| T51 | `状态记录: ` 为空 → 「字段数 = （期望 9）」判红，连带历史样本数判红 | **不是产品缺陷，是台架把记录定位写死了旧格式** |

### 4.2 台架侧的两处修正（都是台架自己的问题，不是产品的问题）

| # | 问题 | 修法 |
|---|------|------|
| 1 | **记录定位写死旧格式**：`grep '^1\|127.0.0.1\|'` 匹配不到新格式 `1\|127.0.0.1:18097\|` → 产品改口径，整组用例替产品背锅 | 定位改成**格式无关**：按 RULE_ID + host 前缀匹配 `^1\|127\.0\.0\.1[:\|]`，host 与 host:port 两种形态都能定位到同一条记录 |
| 2 | **健康状态 fixture 写成产品已经不再产出的旧形态**（裸 host） → 用例退化成「旧格式兼容兜底分支」，断言照样绿，但**精确索引这条主路径根本没人测** | `_write_health` 改成写**当前格式**（`host:port`），并逐个核对 20 处调用点的端口与规则的 `REMOTE_PORT` 一致（不一致 → 精确键查不到 → 落回兜底 → 行为悄悄改变） |

> 两条规矩已写进 `tests/README.md` 与 `tests/TEST-HARNESS.md` 的硬规矩第 17 条：
> **fixture 的形态本身就是断言的一部分**；**记录定位要格式无关**。

### 4.3 产品又改了一次口径（`bfc99d3`，N1-R1）：去掉裸 host 宽键兜底

Chief 复现的 N1-R1：**同一个主备组内、同 host 不同端口**（`10.0.0.1:111` / `10.0.0.1:222`），
老状态文件里只有 111 的 failed 记录时，222 查不到精确键 → 退裸 host 宽键 → 读到 111 的 failed
→ 两个目标都判 failed → 全挂兜底 → 保持原主不切备（流量压在已故障的主机上）。

`bfc99d3` 的改动：读侧认得出归属时**只**入精确键（不再存一份裸 host 宽键）；认不出归属时**当无记录**；
消费端（主备选主 / 剔除过滤）与展示端（`get_health_status_record`）的「退裸 host 宽键」回退**全部去掉**。

→ **台架里两条断言是按旧语义写的，必须跟着改**（这不是台架在替产品背锅，是断言本身要更新到新口径）：

| 位置 | 旧断言 | 新断言 |
|------|--------|--------|
| T51 展示端 | 旧格式记录**按裸 host 兜底命中** | 旧格式记录**查不到** —— 展示端只认精确键（否则会把同 host 另一个端口的状态显示成这条目标的） |
| T52 兼容 | 认不出归属 → 按裸 host 兜底 → 保守多切 | 认不出归属 → **当无记录** → 那条老记录**不让任何目标被判故障** |

> ⚠️ 「保守多切」这个说法与实际行为相反，**不能写进断言**：宽键会把一个端口的故障
> 传播给同 host 的其他端口 —— 这正是 N1-R1 要消除的静默失效。

### 4.4 T52 补上 N1 真正触发的形态（此前零覆盖）

**为什么必须补**：N1 缺陷的触发形态是「**同一个端口组内**、同 host 不同端口」（主备的标准拓扑），
而原 T52 覆盖的是「两个不同端口组、同 host」。两者触发的是同一段代码路径，但一个走精确键、
一个走宽键回退 —— **只覆盖前者 = 缺陷溜过去的原因**。

`tests/cases/12_health_target_scope.sh`（第 7 轮收尾新增）现在的断言面：

| 断言 | 内容 |
|------|------|
| 写侧 | **同一端口组内**、同 `REMOTE_HOST`、不同 `REMOTE_PORT` → 状态文件里是**两条独立记录**（TARGET 分别是 `host:port`），没被互相覆盖 |
| 读侧·跨端口组 | 端口组 443 的故障目标被剔除；端口组 844 的两个目标都还在 —— **A 组的故障没被 B 组的健康盖掉** |
| 读侧·**同端口组同 host 不同端口** | 主备组 `10.0.0.1:111`（主）/ `10.0.0.1:222`（备）：111 故障时**必须切到 222**（balance = `roundrobin: 0, 1`）；且**旧格式输入与新格式输入的产出逐项一致** |
| 兼容（归属可认） | 旧格式（TARGET 只有裸 host）按 RULE_ID 补出端口 → 隔离照样成立 |
| 兼容（归属不可认） | 认不出归属 → **当无记录** → 两个端口组、两种拓扑下都**不判故障** |

> ★ **验收口径**：写「兼容」时，判据必须是**「新旧两种输入的产出完全一致」**，
> 不是「旧格式不报错」—— 后者会放过宽键泄漏这类静默失效。
> 实操：造**同一逻辑场景**的两份输入（旧格式 / 新格式），跑同一函数，**比对输出**，差异即缺陷。

**T52 的 3 条负向对照：**

| # | 做法 | 期望 |
|---|------|------|
| 1 | 判定器喂「两条记录挤在同一个 TARGET」的探针 | **判红**，原因指到「恰好 1 条」 |
| 2 | 判定器喂「少一条记录」的探针 | **判红**，原因指到「行数」 |
| 3 | **把读侧换回两版历史真实实现**：`a7e23fc`（N1-R1 的直接前态，还留着宽键）与 `f730c8b`（最初那版，只用裸 host 建索引） | 两版都复现出**不切备**（balance = `roundrobin: 1, 0`）；而当前实现是 `0, 1` |

> 负向对照 3 用的是**真实的历史实现**，不是人造的 `sed` 破坏：
> 人造破坏依赖代码写法（实现一改就静默失效），而「同 host 不同端口互相覆盖」这个症状
> 在**修复后的实现上不可达**（精确键一定先于裸 host 兜底命中）—— 想复现它，只能换回旧实现。
> 取不到旧实现就**判红**（负向对照跑不起来 = 没在证明它该证明的事），绝不静默跳过。

### 4.5 顺带修掉一处「顺序依赖假红」

定向跑 `--only T30` 是绿的，跟着 T29 一起跑就红。根因不是产品：
**沙箱跨用例共用**，T29 留下的规则是 `LISTEN_PORT=8080` + `FAILOVER_ENABLED=true`，
T30 的「failover off → 不过滤」场景里读侧按端口组扫**所有**规则文件 → 捡到了那条遗留规则 → 目标数从 3 变 1。
（清理没生效是因为 `reorder_rule_ids` 会把规则文件改名重排 → 遗留文件换了名字仍然在目录里。）

**修法**：T29 / T30 / T31 用例开头**先清空规则目录**。
自查口径：**「单独跑这一条，结果一样吗？」** 全量跑批会掩盖这类问题，**定向跑才是照妖镜**。

### 4.6 台架自身踩到的三个坑（都写进硬规矩了）

| 坑 | 现象 | 纪律 |
|----|------|------|
| 「设全局变量的函数」被写进 `$(...)` | 命令替换开子 shell → 全局变量赋值丢失 → 拿到空串 → 源文件加载失败 → **负向对照静默返回空值**（看着像「症状没复现」，其实是根本没跑起来） | 设全局变量的函数**必须在当前 shell 调用**，不要写进命令替换 |
| 观察量选错 | 剔除模式下「全挂兜底」只剩一个目标 → `extra_remotes` 为空 → **根本不输出 `balance` 字段** → 症状观察不到 | 这种场景用**主备模式**观察（两个目标都留在列表里，health 状态只体现在权重上） |
| 断言只看数值 | 「1,0」既可能是「不切换的缺陷」，也可能是「全部目标都挂了 → 走全挂兜底」的**正确行为** | 必须同时记录**场景**和**新旧是否一致**，否则会把正确行为当缺陷修 |
