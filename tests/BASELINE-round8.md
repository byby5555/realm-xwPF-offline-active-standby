### 2.2 T45 的「本机可跑的等价断言」——skip ≠ 放过

ETXTBSY 是 **Linux 内核**行为 → Git Bash/Windows 上「跳过」等于那一半没测。
按 Chief 的要求补了一条**不依赖内核行为**的等价断言：

| 判据 | 依据 | 适用范围 |
|------|------|---------|
| 恢复一个**非运行中**的二进制后，**目标文件的 inode 必须变化** | 原地 `cp` 覆写 → inode 不变；替换（`mv`/rename）→ inode 变。这是「会不会撞 ETXTBSY」的**可观测代理** —— 断言的是**效果**，不是命令名 | 任何平台（Windows 上 inode 由 MSYS 提供，Linux 上是标准 inode） |

本轮实测：`idle_inode_before=5066549582477472` → `idle_inode_after=4785074605766825`（**变了**）✓，`idle_rc=0`、`idle_content=1` ✓。
**这条断言让「修复前的冻结点 `6df4721`（直接 cp 覆写）」在本机也能判红** —— 以前做不到。

## 4. 过程中抓到的台架自身假绿（T45 的相对路径）

**症状**：T45 的「覆盖正在运行的二进制」子项一直是绿的，但它**根本没测到那件事**。

**根因**：restore 把备份文件恢复到 `"/${rel}"`（绝对路径），所以备份里的**相对路径**必须是
`$site` 去掉**一个**前导斜杠。旧写法是 `"tmp/${site#/}/busy.bin"` → `/tmp` 被拼了两遍 →
目标目录 `"/tmp/tmp/xwpf-sbx.XXX/..."` **根本不存在** → 恢复必然失败。
本机恰好走的是「Windows 语义」分支（只要求「不许静默失败」）→ 失败被当成「被系统锁住」→
**一路绿灯**。也就是说：这一子项在真机上会红、在本机上假绿，且**红的原因还不对**。

**发现方式**：本轮给 T45 补的 inode 等价断言（2.2）在**非运行中**的目标上也失败了
（`idle_rc=1`）→ 立刻暴露「不是锁，是路径」→ 手工在沙箱里复现，打出真实报错：
`cp: cannot create regular file '/tmp/tmp/xwpf-sbx.XXX/.../idle.bin.restore.2184': No such file or directory`。

**修法**：相对路径改成 `"${site#/}/busy.bin"`；并加一条护栏
`busy_target_dir` / `idle_target_dir` —— 目标目录不可达时**明确 skip**（不假装测过）。
修完后本机实测：`busy_restore_rc=0`、`busy_content=1`、`idle_rc=0`、`idle_content=1`、
inode 变化 ✓。

**顺带发现台架说错了话**：路径 bug 未修时，「恢复失败」被误归因为系统锁，
于是 T45 写下「连 mv（改目录项）也绕不过」。修好后实测 **Windows 上 mv 能替换运行中的 exe**
（被挡住的只有直接 `cp`）—— 这正好**证明**「必须走 mv 覆盖」。台架的日志文字照实改（v2.8.1），
**断言只加强、不放松**。

> **元教训（已写进硬规矩第 22 条）**：**假绿最常见的形态不是「断言写错」，而是「断言测的不是那件事」。**
> 「通过」不等于「测到了」—— 必须问一句：**这条用例真的跑到了它声称要测的路径吗？**
