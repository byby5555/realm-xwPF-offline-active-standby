# 门禁四件套的 BASE_SHA 悬空问题（`ddfb492` ⇒ 建议改写为 `c552d8e`）

> **性质**：**引用纪律问题** —— 不是产品缺陷、不是台架缺陷，**也不推翻任何门禁结论**。
> 审稿在核对 Chief 交来的最终门禁四件套时当场核出；本条只登记事实、证据与建议修法。
> 核验时间：2026-10-25 上午；**全程只读**（未改 `lib/`、`tests/`、`docs/`、`cmd/`，未做 git 写操作）。

## §1 现象：四件套给的 BASE_SHA 挂在任何分支之外

- 四件套给的 BASE_SHA = **`ddfb49287f88985b24f0b61aad7cdc4310deefdf`**。
- 审稿当场核（两种问法都问过）：

  ```bash
  git for-each-ref --contains ddfb49287f88985b24f0b61aad7cdc4310deefdf --format='%(refname)'
  git branch -a --contains ddfb49287f88985b24f0b61aad7cdc4310deefdf
  # 两条都【无输出】⇒ 该提交不在任何分支上
  git cat-file -t ddfb49287f88985b24f0b61aad7cdc4310deefdf
  # commit ⇒ 对象本身还在
  git reflog --all --format='%h %gd %gs' | grep ddfb492
  # feat/chief-n5-v2@{4}  commit: docs(台架): 退出码 4/5 进契约 + 汇总行末列「预期红」+ 台架升 v2.15.0
  # worktrees/chief-wt-n5v2/HEAD@{7}  commit: 同上
  ```

- ⇒ **只剩 reflog 保命 ⇒ 会被 gc** ⇒ **引用它等于引用一个随时会消失的对象**。
- ★ **迷惑点**：`git cat-file -t` 仍返回 `commit` ⇒ 本地查得到、内容也读得到 ⇒
  **只核「对象在不在」核不出「引用已失效」** ⇒ 必须问「**还在不在任何分支上**」。

**起因**：Chief 分支在 07:35 / 07:55 **连 rebase 两次**，把同一棵树换了新 SHA；
`ddfb492` 是被换掉的那一个旧 SHA，它的新形态是 `c552d8e`。

## §2 好消息：内容完全等价 ⇒ 结论可平移，**只需换 SHA**

  ```bash
  git rev-parse c552d8e:tests      # b8b153faafeea5c014fb7050007c852a45147236
  ```

  （57 个 blob，一一对应。）

- ⇒ **建议把四件套的 BASE_SHA 直接改写为 `c552d8eeda967b390f92a88c63284c00435a71bc4`**
  ⇒ **四件套的其余内容一字不动** ⇒ 结论、条数、汇总行、退出码全部不变。

## §3 顺带一条（性质不同，别与 §1 混为一谈）：台架指纹那个值**口径复算不出来**

- 四件套给的台架指纹（第 ⑦ 样）= **`9f92d5752ee7e96a8b3d63a25e8becc5`**。
- 审稿试了 **12 种常见口径**（git blob 哈希集合 / 「`hash  path`」清单 / 文件内容 sha256 清单 /
  md5 变体 / sha256 变体，含**直接对跑批那个克隆的工作区**算）⇒ **都没复算出这个值**。
- ⇒ **拿它的人无法自证它绑的是哪份台架** ⇒ 建议把第 ⑦ 样的**口径写死成可复算算法**，并给一份实测值。
  审稿给的一个可复算口径示例：「`git ls-tree -r <SHA> tests/` 的 blob 哈希按路径排序后取 sha256 前 32 位」
  ⇒ 审稿在 `c552d8e` 上实测 = **`c533044edfc4a99fc7d6a26b23197daf`**（57 个 blob）。
- ★ **但它要认证的那个性质，审稿能独立证明**（这才是关键，结论不依赖那个值）：

  | 比对项 | 结果 |
  |---|---|
  | 跑批克隆 `chief-gate-n5v4` 的 `tests/` 文件数 | **57**（与冻结点树 `tests/` 的 blob 数相同） |
  | 两边**字节级完全相同**的文件 | **44** |
  | 另 13 个（11 个 `tests/shims/*` + `tests/baseline-manifest.txt` + `tests/commit-msg-exemptions.txt`） | 差异**纯是 Windows 检出的 CRLF**（去掉 CR 后**完全相等**；`shims` 在树里是 mode `100644` 普通文件，**不是 symlink**） |
  | 归一化（去 CR）后整体 | **57 / 57 逐字相同** |
  | `lib/` 7 个被测产物文件 | **字节级完全一致** |

  ⇒ **「跑批用的台架 = 树里的台架」成立 ⇒ 第 ⑦ 样的实质满足。**

## §6 纪律（跨项目，可复用）

1. **引用任何「不在主干上、且归属方可能还在动」的分支上的 SHA，必须同时写内容指纹**
   （本例是 blob 哈希 / 树哈希）⇒ rebase 只换基线、**内容不变** ⇒ 结论可平移，只换 SHA。
2. **核引用有效性用「还在不在任何分支上」**（`git for-each-ref --contains` / `git branch -a --contains`），
   **不要只核 `git cat-file -t`** —— 后者只答「对象在不在」⇒ **两者要一起看**
   （对象在 + 不在任何分支 = 悬空 = 会被 gc）。
3. **指纹值本身要能被复算**：写「某算法 + 某实测值」，而不是只给一个十六进制串
   ⇒ 否则下一个引用它的人**无法自证它绑的是哪一份**。
4. **「引用失效」与「指纹不可复算」是两件事**：前者是**可达性**问题（可平移），
   后者是**可验证性**问题（要补算法）⇒ 别混为一谈，也别因为后者就说前者不成立。
