## 四、发现 1（当时的🔴）：T54 未登记 = 零覆盖

台架的用例表是**硬编码**的 `CASES=( ... )` 数组，而用例文件按目录自动 `source`：

```

...
CASES=( ... "T53:case_T53_menu_eof_no_busy_loop" )      # 但登记表是硬编码的
```

⇒ 新用例文件**会自动被 source**（函数定义了），但**不在登记表里就永远不会被执行**。

**实测**（未登记时）：


## 七、发现 4/5/6：T54 判定器本身的三处可改（🟠/🟡，**入库版仍存在**）

这一节是**逐条形态实测**判定器的结论，不是读代码猜的。**探针都建在入库版 `b71a9a3` 的判定器上重跑过一遍。**

### 7.1 组合盲区：`read -n 1 -s` 两层都不抓（🟠）

最小探针（`while true` 循环 + `read -n 1 -s`，**故意不加 sleep 兜底**）逐层测：

| 判定层 | 结果 |
|---|---|
| 静态 2（裸 read） | **不报** —— `grep -vE 'read -n '` 把它豁免了 |
| 静态 3（缺 sleep 兜底） | **不报** —— 静态 3 的「含输入读入」判定**不认** `read -n 1 -s` |
| **合计** | **完整逃逸** |

对照：同一循环把 `read -n 1 -s` 换成 `read -p` → **静态 2、静态 3 两层都报出来** ✔

**为什么这是洞**：`read -n 1` 在 EOF 时**同样立刻返回非 0**（不阻塞）→ 变量为空 → `case` 不匹配 → 回到循环顶 → **正是 N1 的形态**。

**建议改法**：**静态 3 的「含输入读入」判定必须独立于静态 2 的豁免面** —— 只要循环体里出现任何 `read` 调用（含 `read -n`、含 `read -rt`），就算「含输入读入」，从而必须要求 `sleep` 兜底。**两层判据不能互相放过。**

### 7.2 静态 2 的豁免面过宽（🟠）

逐形态实测（每个探针单独一个目录，避免串扰）：

| 形态 | 静态 2 的判定 |
|---|---|
| `read -p "..." choice`（裸） | 报出来 ✔ |
| `read -p "..." choice \|\| true` | **豁免** |
| `read -p "..." choice \|\| choice=""` | **豁免**（用例注释声称的可接受形态 ✅） |
| `read -r -p "..." choice \|\| true` | **豁免** |
| `read -n 1 -s choice` | **豁免**（用例注释声称的单键读形态 ✅） |
| `if read -p "..." choice; then` | 报出来 ✔ |
| `x=$(read -p "..." choice)` | 报出来 ✔ |

**问题**：豁免是**一刀切的 `grep -vE '\|\|'`** —— 只要行里有 `||` 就放过。**但 `|| true` 与 `|| VAR=""` 语义完全不同**：
- `|| choice=""` —— 注释把它列为「显式兜底」，可接受；
- `|| true` —— **什么也没兜**，EOF 时变量为空 → 回到循环顶 → **正是要防的病**。

**建议**：把豁免改成**按形态精确匹配**（例如只放行 `\|\|\s*[A-Za-z_][A-Za-z0-9_]*=""`），不要用「含 `||` 就放过」。**否则一个 `read -p ... || true` 能从两层判据下完整溜过去。**

### 7.3 静态 3 的循环定位（🟡）

**定位**：用「**同缩进的第一个**内容恰为 `done` 的行」定位循环结束 ⇒ `done` 带尾串或缩进不同就**漏掉整个循环**。

**实测**（入库版判定器，探针把 `done` 改成 `done || true`）：

```
RESULT=not_reported  → 静态3 把这个循环整个漏掉了
```

⇒ **覆盖洞**（既不报违规、也不计入覆盖）。

**建议**：改用 `do`/`done` **词计数**配对（bash 里天然配平），或至少把 `done` 的匹配放宽到「同缩进且以 `done` 开头」。另外「**前 6 行**」是魔数 —— `sleep` 放在第 7 行就误报，**建议钉语义位置**（循环体首行到读入行之间），不要钉行数。
