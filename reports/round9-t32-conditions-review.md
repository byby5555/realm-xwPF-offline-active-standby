## 二、新发现 1：扫描范围下限护栏测的不是它声称要防的病 🔴

### 2.1 现状

`tests/cases/04_legacy_merged.sh` 的 `_t32_scan_stale` 之外有一条下限护栏：

```bash
# 扫描范围下限护栏：实测候选文件 28 个（6a1e8a1），取约一半。
# 作用：挡住「扫描器一个文件都没扫 → 违规数必然 0 → 假绿」。
_T32_SCAN_FLOOR=14
...
h_check_ge "$_T32_SCAN_FLOOR" "$T32_SCAN_N" "条件 5 的扫描范围下限护栏（扫描到的候选文件数）"
```

`h_check_ge` 的参数序我查过（`tests/lib/harness.sh` 的 `h_check_ge`）：`h_check_ge <floor> <actual> <desc>` → `[ "$actual" -ge "$floor" ]`。**参数序没错位，护栏不是恒绿** —— 这一点先排除掉。

### 2.2 手法 A（台架层级实证）

**只改** `tests/cases/04_legacy_merged.sh` 的 `_t32_candidate_list`，把 `docs/*` 从候选范围里去掉（其余不动），在干净克隆里跑：

```
BASE_SHA=02cc0e6 bash tests/run_tests.sh --only T32
→ 退出码 0
→ 汇总: 总计 1 条，通过 1，失败 0
```

**T32 照样绿。** 逐字复刻的独立复扫给出同一结论：

```
范围=all 但排除 docs/ : N=22（≥14 ✓）命中=0     → 护栏通过（绿），而 docs/ 已不在扫描范围内
```

### 2.3 它漏掉的是什么

往 `docs/` 注入一句真违规后：

```
→ 命中 0 条  ★★ 漏判（docs/ 已逃出扫描范围，护栏却不响）
```

⇒ **护栏防的是「范围被砍到 < 14 个文件」，不是「范围没覆盖到出事的地方」。**
`docs/` 只有 6 个文件，砍掉它 N 还有 22 → 护栏不响 → **那 6 份文档里的误导句式彻底无人检查，而门禁是绿的**。

对照（范围收窄到只剩一半时，护栏**会**红，说明它不是完全没用）：

```
范围=libonly  : N=8  → 护栏会红
范围=docsonly : N=6  → 护栏会红
```

**所以这不是「护栏无效」，是「护栏的作用范围比它的注释声称的窄」** —— 它只挡「全砍」，不挡「砍一部分」。

### 2.4 建议（交阿测）

把护栏从「**文件数下限**」改成「**锚点文件必须在范围内且被扫到**」：

1. **加一条锚点断言**：候选清单（`_t32_candidate_list` 的输出）**必须包含**那几份**已知出过这个毛病的文件** —— 至少 `docs/active-standby-logic.md` 与 `docs/health-check-and-failover.md`；并且这些文件**必须真的被扫到**（`T32_SCAN_N` 之外再记一个「锚点命中数」，断言 ≥ 锚点个数）。
   - 这才是**不变式**（「扫描器真的看了出事的地方」），不随文档总数增减而失效；魔数 `14` 是**结构**，不是不变式。
2. **`_T32_SCAN_FLOOR` 可以保留但降级为辅助**（或直接删掉）：它只防「全砍」这一种最粗的破坏，锚点断言已经覆盖了它，且更准。
3. 负向对照 5/6 的合成探针树**保持隔离**（那个做法是对的：真实缺陷会混进计数）。但**另加一条负向对照**：把候选清单的 `docs/*` 去掉 → 锚点断言**必须变红**（证明这条新断言有牙齿）。

## 三、新发现 2：否定词「整行豁免」是一条漏判通道，而负向对照 6(b) 把它固化成了「正确行为」 🔴

### 3.1 现状

`_T32_NEG_RE='不需要|不存在|无需|无须|不再|不必|不用|不涉及|并非|没有'`，命中后**整行豁免**。

### 3.2 手法 B（台架层级实证）

**只改** `tests/cases/04_legacy_merged.sh` 的负向对照 5，把注入行从「改动需两处同步」换成「**肯定误导句式 + 句尾否定词**」：

```
'# T32-NEG-STALE: 改动 check_connectivity 实现时两处必须同步，没有别的办法。'
```

```
BASE_SHA=02cc0e6 bash tests/run_tests.sh --only T32
→ 退出码 1
→ 汇总: 总计 1 条，通过 0，失败 1
→ 负向对照 5：注入「改动需两处同步」后条…  FAIL
```

⇒ **现行判据抓不到这一行**：它含「必须两处同步」（肯定误导），但同一行有「没有」→ 整行豁免 → 命中数 0 ≠ 期望 1 → 负向对照 5 判红。

### 3.3 合成探针对照表（逐字复刻判据）

| 行文 | 现行判定 | **应然** |
|---|---|---|
| 「改动 check_connectivity 实现时**两处必须同步，没有别的办法**。」 | 豁免 | **计入违规** ← 漏判 |
| 「改动 check_connectivity 实现时**两处必须同步，另外说明一下，我们没有做别的处理**。」 | 豁免 | **计入违规** ← 漏判 |
| 「改动 check_connectivity 实现时**两处必须同步（现在不再需要手工同步）**。」 | 豁免 | 前半句仍在说「要动两处」→ **计入违规** ← 漏判 |
| 「改动 check_connectivity 实现时**不需要两处同步**。」 | 豁免 | 豁免 ✓ **正确** |
| 「改动 check_connectivity 实现时**两处必须同步**。」 | 计入 | 计入 ✓ **正确** |

### 3.4 关键：**负向对照 6(b) 用的正是第三种行文，期望是「必须保持绿」**

`tests/cases/04_legacy_merged.sh` 的负向对照 6(b) 注入的是：

```
'# T32-NEG-NEG2: 改动 check_connectivity 时两处必须同步（现在不再需要手工同步）'
```

期望 `T32_STALE_HITS == 0`（保持绿）。**这一行前半句「改动 check_connectivity 时两处必须同步」本身就是肯定误导句式** —— 后半句括号里的「现在不再需要手工同步」是对前半句的**否定**，不能抵消前半句的假话。

⇒ **负向对照 6(b) 把一个漏判写成了「正确行为」**。这正是 `tests/README.md` 第 22 条 ③ 与 `tests/TEST-HARNESS.md` 第 19 条 ③ 说的那件事：**「期望值本身也可能写错」**。这一条现在有了一个具体的实例。

### 3.5 建议（交阿测）

1. **把豁免从「整行」缩到「子句」**：把行按分隔符（`。！？；，、（）`）切成子句，**逐子句**判定 —— 某子句含肯定误导句式、且该子句内（及紧邻左侧）没有否定词 → 计入违规。
   - 「不需要两处同步」→ 否定词在命中片段**左侧紧邻** → 豁免 ✓
   - 「改动…两处必须同步，没有别的办法。」→ 子句 1 无否定词 → 计入 ✓
   - 「改动…两处必须同步（现在不再需要手工同步）。」→ 括号单独成子句 → 子句 1 无否定词 → 计入 ✓
2. **⚠️ 分隔符必须按字节切、并钉 `LC_ALL=C`** —— 中文标点的 UTF-8 字节是固定的（`，`=`e3 80 84`、`。`=`e3 80 82`、`（`=`ef bc 88`、`）`=`ef bc 89`），**按字节切是稳定的**；这与 P1 的修法方向一致（**分隔用字节、窗口用字节、locale 钉死**），**不要再引入中文标点字符类**（那正是 P1 的病根）。
3. **负向对照 6(b) 的期望要跟着改**：它现在钉的「这一行必须豁免」是一个漏判口径。建议把它拆成两条：
   - 6(b-1)「**不需要**两处同步」→ 必须豁免（真否定句）；
   - 6(b-2)「…两处必须同步（现在不再需要手工同步）」→ **必须计入**（前半句是误导）。
   改完后，**负向对照 6(b-2) 就是新口径自己的牙齿**。
4. **顺带**：否定词表里 `没有` 的覆盖面最大（「没有别的办法」「我们没有做别的处理」都被它兜住），建议在子句口径下**单独看**它，别让它一个人撑起整行的豁免。
